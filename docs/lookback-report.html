1. Method

The script reads the plain-text user prompts from the 20 most recent Claude Code session files on one machine. It skips meta lines, command tags, tool results and prompts shorter than 8 characters. Each prompt, cut to its first 300 characters, goes to Jev as one choice question: "What kind of step is this request from a user to a coding agent?" There are seven kinds. Four are decision kinds: classify_route, pick_from_list, yes_no_check and score_rank. A prompt counts as a candidate when Jev picks a decision kind at probability 0.6 or more.

The two large kinds, research and build, total 93 prompts (82.3%). They ask for investigation, explanation, a document, code or a multi-step task. A decision model that only picks from a given list cannot do them.

3. The 12 decision-type prompts, read by hand

Jev labels the kind of request. It does not check whether it could answer the request. I read the 12 prompts that passed p ≥ 0.6 and sorted them by whether a Jev call could do the job when given the right evidence.

4. What this means

  • The usage pattern is fine. Most prompts ask for work that needs a language model, and that is what a coding agent is for.
  • At the prompt level, Jev could take over about 3 of 113 prompts (2.7%) by my reading, and only with evidence supplied. The saving is small.
  • The better place for Jev is inside the agent's own steps: which file to open, which skill to load, did the tests run. The existing skill-router, verify and coding-reflex builds work there.

5. Limits of this report

  • One run, one machine, one day, 20 sessions, 113 prompts. The shares are not stable estimates.
  • Jev saw only the first 300 characters of each prompt and none of the replies or files. A short follow-up is labelled without its context.
  • The kind labels were not compared with hand labels. Only the 12 candidates were checked, by one reader.
  • The script reads user prompts only. It does not read the agent's tool calls, which is where most decision steps happen. That is not built.
  • This page contains counts only. Prompt text, file paths, project names and personal details are left out on purpose.
